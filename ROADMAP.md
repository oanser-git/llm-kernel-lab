# Roadmap

Follow the numbered directories strictly: finish Lab 00, then open Lab 01, and continue until Lab 26. Do not complete all kernel labs and postpone the model; Lab 20 intentionally produces the first working LLM before the later optimization labs.

Assumption: 10-15 focused hours per week. Move by completion gates rather than dates. GEMM, attention, and the baseline engine may each take several weeks.

## Phase 1: GPU Execution And Memory

**Labs:** 00-04

Learn the machine before implementing transformer mathematics. Finish this phase able to explain threads, warps, blocks, launches, bounds checks, coalescing, shared memory, synchronization, bank conflicts, and asynchronous execution.

**Gate:** You can predict the addresses generated by one warp and use profiler evidence to explain why two correct kernels have different memory performance.

## Phase 2: Reductions And Transformer Primitives

**Labs:** 05-09

Build the reduction and elementwise operations repeatedly used inside transformer blocks: reductions, softmax, RMSNorm, RoPE, and SwiGLU.

**Gate:** You can explain stable reductions, storage versus accumulation dtype, and exactly which global-memory traffic an operator fusion removes.

## Phase 3: Matrix Multiplication

**Labs:** 10-13

Progress from mathematically obvious GEMM to shared-memory tiling, register tiling, and Tensor Cores. Vendor GEMM is the production baseline; your implementations teach why it is difficult to match.

**Gate:** You can derive the data reuse of a tile, identify register/shared-memory limits, verify Tensor Core execution, and compare fairly against cuBLASLt or CUTLASS.

## Phase 4: Attention And Autoregressive State

**Labs:** 14-19

Begin with explicit attention stages, derive online softmax, remove the full score matrix, design the KV cache, implement decode attention, and select the next token.

**Gate:** You can explain why prefill and decode have different shapes and bottlenecks, and every operation required for one transformer layer now has a correct reference implementation.

## Phase 5: First Working LLM

**Lab:** 20

This is where the kernels become a real model. Complete the milestones in order inside `labs/20_full_llm_engine/milestones/`:

1. Load configuration and SafeTensors weights.
2. Match one transformer block.
3. Match full-model logits.
4. Implement prefill and populate the KV cache.
5. Implement KV-cached decode.
6. Accept text and return generated text.

**Gate:** One identified small dense Qwen checkpoint runs end to end and matches independent PyTorch logits and greedy tokens. Do not begin optimization labs until this baseline is correct.

## Phase 6: Optimize And Scale The Engine

**Labs:** 21-25

Each lab begins with an isolated experiment in its descriptively named student `.cu` file, then integrates the proven behavior into the same Lab 20 engine. Do not copy the complete engine into these directories.

**Gate:** Streams and graphs provide measured improvements where used, quantization has documented model-level error, paging preserves logical cache contents, and batched execution matches independent batch-one results.

## Phase 7: Multiple Model Families

**Lab:** 26

Use the working Qwen engine to discover real architecture boundaries. Add one identified Llama checkpoint, then one identified Gemma checkpoint.

**Final gate:** Qwen, Llama, and Gemma each match reference logits and greedy generation; unsupported features fail clearly; time to first token, prefill throughput, decode latency, tokens per second, and memory use are reported.
