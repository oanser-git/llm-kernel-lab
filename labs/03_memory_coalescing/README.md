# Lab 03: Memory Coalescing

## Goal

Measure how address patterns generated by neighboring warp lanes affect memory transactions and useful bandwidth.

## Write

- A contiguous copy or transform kernel.
- A strided-access variant with configurable stride.
- An offset-access variant with configurable starting offset.
- A simple gather using an index array.
- CPU validation that distinguishes logical layout from physical addresses.

## Test Matrix

Sweep element sizes or vector widths, offsets, strides, block sizes, and array lengths. Include strides around powers of two and ensure every tested access remains in bounds.

## Benchmark

Compare requested bytes with achieved throughput. Use Nsight Compute to inspect global load/store sectors or equivalent memory-transaction metrics available on the GB10.

## Questions

1. What does coalescing mean at the warp level?
2. Why can aligned allocation still produce uncoalesced accesses?
3. How do cache hits complicate a simple bandwidth interpretation?
4. Which LLM operations naturally perform gather-like access?

## Complete When

The report includes a stride/offset experiment, profiler evidence, and an explanation connecting lane addresses to observed transactions.
