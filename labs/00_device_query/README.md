# Lab 00: Device Query

## Goal

Discover the actual GB10 properties exposed by the CUDA runtime and connect each property to a future kernel-design decision.

## Write

- Select a CUDA device and retrieve `cudaDeviceProp`.
- Print compute capability, warp size, maximum block dimensions, thread limits, SM count, clock information, global memory, shared memory, register limits, L2 size, memory-bus information when available, and managed-memory capabilities.
- Calculate values only when the necessary properties are exposed; label unavailable values instead of inventing them.
- Explain why `nvidia-smi` may not report conventional dedicated VRAM on this unified-memory system.
- Add error checking around every CUDA runtime call.

## Verify

- Compare device name and CUDA version with `nvidia-smi` and `nvcc --version`.
- Confirm the program handles an invalid device index cleanly.
- Record the complete report in `REPORT.md`, along with what each important property constrains.

## Questions

1. Which limit controls the maximum threads in one block?
2. Which resources can reduce resident blocks per SM?
3. Which reported values are theoretical limits rather than achieved performance?
4. What does unified addressing guarantee, and what does it not guarantee?

## Complete When

The report is generated by your own program, errors are handled, and you can explain how at least five properties affect later labs.
